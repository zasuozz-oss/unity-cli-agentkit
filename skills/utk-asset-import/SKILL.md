# Importing External Assets — file path, never base64

The official CLI's `import_asset` tool copies a file from anywhere on disk
into `Assets/` and imports it in one call. `utk import` wraps it. There is
**no reason to move image bytes through the model context**: base64 inside an
`utk exec` snippet costs ~1.4 tokens per byte, hits the eval payload and
timeout limits on anything bigger than an icon, and re-implements what the
tool already does.

## The flow

1. **Get the bytes onto disk first** — outside Unity, with ordinary tools:
   - Downloaded file → `curl -o /tmp/hero.png <url>`
   - AI image API answering base64 → decode in the shell/Python to a temp
     file (`base64 -d > /tmp/hero.png`), never inside an exec snippet
   - File generated by a script → it is already on disk
2. **Import** (source may be relative; utk resolves it and refuses a missing
   file before anything is sent):

   ```sh
   utk import /tmp/hero.png UI/Textures/hero.png
   ```

   The destination is relative to `Assets/` and defaults to the file's own
   name. The answer carries what a follow-up would otherwise cost a call for:

   ```json
   {"assetPath":"Assets/UI/Textures/hero.png","guid":"50868481…","fileId":2800000,"type":"Texture2D"}
   ```

3. **Tune the importer if needed** — import settings are importer state, not
   file bytes, so they go through the tools, never text edits (see
   `utk-asset-edit`):

   ```sh
   utk set_import_settings --asset Assets/UI/Textures/hero.png \
     --settings '{"textureType":"Sprite","spritePixelsPerUnit":100}'
   utk get_import_settings --asset Assets/UI/Textures/hero.png   # verify
   ```

## Rules

- ✅ Overwriting an existing asset needs `--confirm true`; without it the
  call fails and `utk` exits non-zero. Check first or pass it deliberately.
- ✅ `--dry_run true` validates source + destination without writing —
  cheap insurance before a batch.
- ✅ A batch of files is N quick `utk import` calls run sequentially in your
  own context — do not spawn a subagent for it, and do not try to fold the
  copies into one exec snippet.
- ✅ Per-platform texture overrides go through the same tool:
  `utk set_import_settings --asset <path> --platform Android --settings
  '{"maxTextureSize":1024,"overridden":true}'`.
- ❌ **NEVER** `System.Convert.FromBase64String` + `WriteAllBytes` inside
  `utk exec` to smuggle a file in.
- ❌ **NEVER** write files into `Assets/` and stop there — an un-imported
  file is invisible to the Editor until a refresh. `utk import` does the
  copy *and* the import; if you wrote the file yourself, run
  `utk editor refresh` afterwards.

## The reverse direction (Unity → you)

The same principle applies to output: `utk screenshot` already saves to a
file and answers with a path. For the raw capture tools
(`capture_scene_view` / `capture_game_view`), always pass `--save_path` — the
default answer inlines the PNG as base64 into your context.
